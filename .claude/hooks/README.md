# .claude/hooks

## Purpose

Claude Code hooks v0: the early-warning half of the guardrails. They refuse rule-breaking changes **before** they
land, put the right module guidance in front of Claude, and stop Claude from handing back work that fails the docs
gate or the rules. CI (`tools/build.ps1 -Target CI`) runs the same rules and is the authoritative gate; the hooks
only make failures cheaper (ADR-006).

| Event | Script | What it does |
|-------|--------|--------------|
| `SessionStart` | `session-start.mjs` | Adds a short guardrail briefing: CI is authoritative, compiled-rules status and module list, module roots, platform-owned and generated paths. |
| `UserPromptSubmit` | `user-prompt-submit.mjs` | Adds the intent → skill routing table (`routing-table.json`) and the likely match for the prompt. |
| `PreToolUse` `Edit\|Write\|Bash\|PowerShell` | `pre-tool-use.mjs` | Refuses violating edits with rule id + fix; injects the module's MODULE.md/CLAUDE.md once per session. |
| `Stop` | `on-stop-gate.mjs` | On changed files (git status): docs gate, compiled-rules drift check, whole-file rules check. Blocks the stop with the reasons. |

Wiring and the permission deny rules live in [`../settings.json`](../settings.json).

## Use

Nothing to run: Claude Code calls the hooks. To try one by hand, pipe hook input JSON into it:

```powershell
'{"cwd":"E:/codelab-starter","tool_name":"Write","tool_input":{"file_path":"E:/codelab-starter/backend/src/A.cs","content":"var t = DateTime.Now;"}}' |
  node .claude/hooks/pre-tool-use.mjs
```

Tests (CI step 5): `node --test ".claude/hooks/tests/**/*.test.mjs"`.

Environment:

| Variable | Effect |
|----------|--------|
| `CLAUDE_PROJECT_DIR` | Project root (set by Claude Code). Falls back to the input `cwd`. |
| `CODELAB_PLATFORM_OWNER=1` | Unlocks Edit/Write under `rules/**` and `packages/**` (platform owner only; CODEOWNERS review still applies). |
| `CODELAB_DOTNET` | dotnet used by the Stop gate for the docs gate. Else `E:\codelab-tools\dotnet10\dotnet.exe` if present, else `dotnet`. |
| `CODELAB_DOCS_NOT_NEEDED` | Passed through to the docs gate (the `Docs-Not-Needed:` override). |

### What PreToolUse refuses

Each refusal is `permissionDecision: "deny"` with a `permissionDecisionReason` that starts with the rule id and ends
with `Fix: ...`. The hooks never answer `allow`: when they do not refuse, the normal permission flow applies.

| Rule id | When |
|---------|------|
| *rule id from rules.compiled.json* | Edit: `old_string → new_string` is applied in memory to the current file and the **whole resulting file** is evaluated. Write: the new content is evaluated. Only violations the change **introduces** are refused (see Rules). |
| `hooks.generated-file` | Edit/Write (or a shell write) to `rules/*.compiled.json`, `**/BannedSymbols.generated.txt`, `docs/generated/**`, `feed/**`, any `generatedFiles` glob from the compiled rules, or a file whose head carries a generated marker (`GENERATED by tools/rules-engine`, `<auto-generated`, `@generated`). Applies to the platform owner too. |
| `hooks.platform-owner` | Edit/Write under `rules/**` or `packages/**` without `CODELAB_PLATFORM_OWNER=1`. |
| `hooks.module-without-rules` | A file in a module folder (`<module root>/<Name>/...`) that has no `module.rules.yaml`, i.e. a new module started by hand. `module.rules.yaml` and `MODULE.md` themselves are allowed (scaffold order). The message names the `new-module` skill. |
| `hooks.no-shell-source-writes` | Bash/PowerShell that writes into a source path: redirects `>` `>>` `&>` `2>` (incl. heredocs), `tee`, `sed -i`, `perl -i`, `Set-Content`/`Add-Content`/`Out-File`, `[IO.File]::Write*`, also inside `bash -c` / `powershell -Command`. A source path is inside the project and not gitignored. When the written text is known (heredoc, echo, `-Value`), its rule violations are listed too. |

### Module context injection

When Edit/Write touches a module folder, the hook adds `additionalContext` with the compiled module description plus
the head of the module's `MODULE.md` and `CLAUDE.md` (1500 chars each), once per module per session (state in
`%TEMP%/codelab-hooks/<session>.json`). It reads the files from disk, so it works for a **new file in a new module**
(where nested CLAUDE.md lazy loading does not fire) as soon as the module has its `module.rules.yaml`; an uncompiled
module gets the base rules plus a note to run the compiler.

## Extend

- **New content rule:** add it to `rules/base.rules.yaml` or a `module.rules.yaml` and run
  `node tools/rules-engine/compile.mjs`. The hooks pick it up from `rules.compiled.json`; no hook change.
- **New hook-owned rule (path policy):** add the id to `HookRuleIds` in `lib/constants.mjs`, the check to
  `lib/path-policy.mjs`, call it from `lib/pre-tool-use-decision.mjs`, add a fixture test and a row above.
- **New shell write form:** extend `lib/shell-writes.mjs` and add a case to `tests/lib.test.mjs`.
- **New route:** add an entry to `routing-table.json` with `skill` (a folder under `.claude/skills`) or `recipe`
  (a doc path). A skill whose `SKILL.md` does not exist is shown as "not built yet". Keep the table in sync with
  the routing table in the root CLAUDE.md.

### Expected `rules/rules.compiled.json` shape

The rules engine (`tools/rules-engine`) owns the format. The hooks read only these fields and ignore the rest:

```jsonc
{
  "schemaVersion": 1,
  "base": {
    "forbidden": [{
      "id": "base.time-provider",            // shown in refusals
      "pattern": "\\bDateTime(?:Offset)?\\.(?:Now|UtcNow|Today)\\b",  // JS regex, run on the WHOLE file
      "flags": "",                            // optional; g/y are ignored (the hook adds g)
      "appliesTo": ["**/*.cs"],              // repo-relative globs (** * ? {a,b}); a glob without / matches the file name
      "excludes": ["**/*.Tests/**"],
      "description": "Reading the system clock directly makes time untestable.",
      "fix": "Inject TimeProvider and call GetUtcNow()."
    }],
    "required": [{ "id": "...", "pattern": "...", "appliesTo": ["..."], "fix": "..." }]  // entries without pattern are skipped
  },
  "modules": [{
    "module": "ServiceRequests",
    "path": "backend/src/Modules/ServiceRequests",
    "description": "...",                     // injected as module context
    "forbidden": [ /* EFFECTIVE list: inherited base rules minus exemptions + own rules */ ],
    "required":  [ /* same */ ]
  }],
  "moduleRoots": [{ "kind": "backend", "path": "backend/src/Modules" }],   // optional; defaults shown below
  "generatedFiles": ["glob"]                                                 // optional; added to the defaults
}
```

Tolerated aliases: `files`/`include` for `appliesTo`, `exclude` for `excludes`, `message` for `description`,
`fixMessage` for `fix`, `regex` for `pattern`, `name` for `module`, `root` for `path`, modules as an object map.
Default module roots: `backend/src/Modules` and `frontend/starter-web/src/app/features` (plan section 2).

## Rules

- Hooks never parse YAML; they read `rules/rules.compiled.json` only. Missing or invalid file → content rules are
  skipped with a `systemMessage` warning, path guards still apply.
- **Ratchet:** a forbidden rule refuses when the resulting file has more matches than before; a required rule
  refuses when the pattern disappears (or a new file lacks it). A file that already breaks a rule can still be
  edited, but not made worse. CI checks the absolute state.
- A hook crash never blocks: it prints a warning and exits 0, because CI is the gate.
- The Stop gate blocks once; when `stop_hook_active` is true it only warns, to avoid an endless loop.
- No magic values: ids, paths, limits and env names live in `lib/constants.mjs`.

## Gotchas

- The shell-write detector is a lexer, not a shell (`lib/shell-writes.mjs` lexes, `lib/shell-commands.mjs` knows
  the commands). It resolves redirects, tee, in-place editors, cp/mv/install/ln/rsync/rm/dd/curl -o/wget -O,
  `git checkout|restore -- <paths>`, PowerShell cmdlets and their aliases (sc, ac, tee, cpi, mi, ri, ni, iwr...),
  `-Param:value` syntax, backtick-escaped names, script blocks (`% { ... }`), `[IO.File]`/`StreamWriter` calls,
  `cd`/`pushd`/`Set-Location` earlier in the same command, and nested scripts (`bash -c`/`-lc`, `env`,
  `eval`, `cmd /c`, `iex`, `-EncodedCommand`).
- **Fail closed:** a write the detector cannot name (a target in a variable, `git apply`, `patch`, `xargs rm`,
  `find -delete`, an inline `python -c`/`node -e`/`perl -e` script that calls a file-writing API) returns
  `permissionDecision: "ask"` ([hooks.unresolved-shell-write]), so the user decides. Only targets that plainly point
  at a temp or home folder (`$TMPDIR`, `$env:TEMP`, `~`, `$(mktemp)`) are allowed without asking.
- A script FILE run by an interpreter (`node x.js`, `python x.py`) is not inspected. That gap is closed by CI:
  step 9 (`tools/rules-engine/check-content.mjs`) evaluates every content rule over every tracked file, and the
  `ask` rules in settings.json cover `git apply`, `patch`, `iex` and copy/move/remove into `rules/`.
- `git check-ignore` decides "source path"; without git every in-project path counts as source (fail closed).
- The PreToolUse matcher includes `PowerShell` as well as `Edit|Write|Bash`, because on Windows `Set-Content` and
  `Out-File` usually arrive through the PowerShell tool.
- The Stop gate diffs against the merge base of HEAD and `origin/main`/`main` (or `CODELAB_BASE_REF`), so a
  change Claude already committed in the session is still checked; the docs gate gets the same `--base`.
- In a repo with no commits every file is "changed", so the Stop gate checks the whole tree (about 3 s here, plus
  the docs gate build on first run).
- Glob matching is case-insensitive (Windows file systems); the rules engine's matcher is case-sensitive.
- Edit and Write are evaluated in memory; no temporary file is written.
- Tests build throwaway projects under the OS temp dir, so fixture `module.rules.yaml` files never enter the repo
  (the compiler and docs gate would pick them up).

## ADR-006 draft: hook architecture

*Draft for the docs builder, who writes `docs/adr/ADR-006-*.md`.*

**Status.** Proposed (Phase 0).

**Context.** Rules written only in prose (CLAUDE.md, standards docs) were ignored by AI agents in the source project.
The starter needs the same rules applied while Claude edits, without a second rule format and without trusting the
editor as the last line of defence.

**Decision.**

1. **CI is the authoritative enforcement; hooks are an early warning.** Every rule a hook enforces is also enforced by
   CI: the content rules by `tools/rules-engine/check-content.mjs` (build step 9, absolute state over every tracked
   file, same evaluator as the hooks), plus the rules drift check, analyzers, architecture/contract tests and the
   docs gate (with `--base`). A hook failure or bypass can delay feedback,
   never let a violation merge.
2. Hooks are **Node `.mjs` scripts** (Node is already a prerequisite) with no npm dependencies, reading
   **`rules/rules.compiled.json`** only. They never parse YAML.
3. **PreToolUse `Edit|Write|Bash|PowerShell`** refuses with `permissionDecision: "deny"`, the rule id and the fix.
   Edit is evaluated on the **whole resulting file** (old→new applied in memory), Write on the new content, and
   shell writes into source paths are refused outright (use Edit/Write so the rules run). Refusals use ratchet
   semantics so legacy violations do not block unrelated edits.
4. **Module docs injection** uses PreToolUse `additionalContext`, read from the module folder on disk, once per
   module per session. This works for a new file in a new module, where nested CLAUDE.md lazy loading does not
   fire. SessionStart adds the guardrail briefing; UserPromptSubmit adds the intent → skill routing table.
5. A new module folder without `module.rules.yaml` is refused and pointed at the `new-module` skill.
6. **Platform-owner check** for the CODEOWNERS paths and every guardrail switch (`rules/**`, `packages/**`,
   `.claude/**`, `deploy/**`, `.github/**`, `docs/adr/**`, `docs/standards/**`, `provenance/**`, `tools/build.ps1`,
   `tools/extract/**`, the frontend lint configs (`eslint.config.mjs`, `stylelint.config.mjs`, `tools/lint/**`), and at any
   depth `Directory.Build.*`, `Directory.Packages.props`, `global.json`, `nuget.config`, `.editorconfig`; see
   `PlatformOwnedGlobs`, kept equal to CODEOWNERS and `build.ps1` by `tests/protected-paths-parity.test.mjs`) and
   for the `exemptions` block of any `module.rules.yaml`, via `CODELAB_PLATFORM_OWNER=1`. Analyzer opt-outs
   (`CodelabEnableBannedApis=false`, `NoWarn`/`#pragma`/`.editorconfig` for RS0030 or CA1502) are the base rule
   `base.no-analyzer-opt-out`. The real gate is
   CODEOWNERS / path-owner review plus CI. Generated files are refused for everyone.
7. **Stop** runs the docs gate, the compiled-rules drift check and the rules check on the files changed since the
   merge base with main (committed or not), and blocks the stop once with the reasons.
9. **Time budget.** Content rules are evaluated in a worker with a wall-clock budget
   (`EvaluationBudgets.PreToolUseMs`); when it runs out the call is DENIED ([hooks.rule-evaluation-timeout]) instead
   of letting the Claude Code hook timeout fail open. The rules compiler also rejects nested unbounded quantifiers.
8. **Permission deny rules** back up the hooks: `git push --force` (all spellings), reading `*.pfx`/`*.p12`/`*.key`/
   `*.pem`, editing `feed/**`, `rules/rules.compiled.json`, `**/BannedSymbols.generated.txt`, `docs/generated/**`.

**Consequences.** Violations surface seconds after Claude writes them, with the fix text. Hooks can be bypassed
(other editors, hooks disabled in local settings, unusual shell forms); that is accepted because CI repeats every check. The
compiled-JSON contract couples hooks to the rules engine's output, so the engine owns the format and the hooks read
a small, documented subset with tolerated aliases.

**Open (spike).** The exit criterion "module docs injection observed in a recorded session that creates a new file
in a new module" needs a live Claude Code session in this repo; the hook output is covered by fixture tests, the live
observation is still to be recorded.
