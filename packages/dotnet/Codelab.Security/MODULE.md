# Codelab.Security

## Purpose
The versioned security core every starter host and service shares (ADR-000, ADR-002). One package owns:

- **Protocol names** from one prefix (`SecurityProtocol`): `{Prefix}-SIG-v1`, `{Prefix}-PUBLICID-v1`, `{Prefix}-CANON-v1`, `{Prefix}-TICKET-v1`, `{Prefix}-RECEIPT-v1`, `{Prefix}-S2S-v1`, headers `X-{Prefix}-Signature`, `X-{Prefix}-Response-Signature`, `X-{Prefix}-Service-Assertion`. Tests and golden vectors use `CODELABTEST`.
- **Canonical framing** (`CanonicalFraming`): `{utf8Length}:{value}\n` per element; the bytes every MAC, AAD and KDF info is built from.
- **Request and response signing** (HMAC-SHA256 under an HKDF-derived per-session key), the signing-key issuance endpoint, `[SignatureExempt]` and `[UnsignedResponse]`.
- **Replay guard**: memory and SQL Server, shared by signing, service assertions and tickets.
- **PublicId**: AES-256-GCM opaque identifiers bound to an identifier family, with minimal-API binding, the MVC model binder, the `publicid` route constraint, a JSON converter and a built-in OpenAPI schema transformer.
- **Edge controls**: security headers (first in the pipeline), CORS validation, the request body ceiling, rate limiting that believes `X-Forwarded-For` only from listed proxies.
- **Key-ring fail-fast guards** with the published-material denylist on by default.
- **Sealed one-time tickets**, **one service-to-service scheme** (ES256 per-request assertions), **upload safety primitives** and **session revocation** (session version + per-`sid` list).

## Use
```csharp
var builder = WebApplication.CreateBuilder(args);
builder.AddCodelabSecurity();                       // binds Codelab:Security:*, validates on start
builder.Services.AddAuthentication(...);            // the host's session scheme (P2/P3)
builder.Services.AddOpenApi(o => o.AddCodelabPublicIds());

var app = builder.Build();
app.UseCors();                                      // before authentication
app.UseRouting();                                   // before UseCodelabSecurity (endpoint policy schemes)
app.UseAuthentication();
app.UseCodelabSecurity();                           // after authentication: rate limiter, sessions, signing
app.UseAuthorization();
app.MapCodelabSigningKeyEndpoint();
```

Configuration (key material comes from the environment or a secret store, generated by `init.ps1`; never from a committed file):

| Section | Required | Notes |
| --- | --- | --- |
| `Codelab:Security:Protocol:Prefix` | yes | `A-Z` then `A-Z0-9`, 2-16 characters. |
| `Codelab:Security:PublicIds` | yes | `ActiveKeyId`, `Keys[]` (`KeyId` `[a-z0-9]{1,8}`, `MaterialBase64` of 32+ bytes). |
| `Codelab:Security:RequestSigning` | when `Mode` is not `Off` | `Mode` (`Off`=0, `Report`=1, `Enforce`=2), `Audience`, `MaxAgeSeconds`, `MaxSignedBodyBytes`, the master key ring. |
| `Codelab:Security:ResponseSigning` | no | `Mode`; needs request signing on. |
| `Codelab:Security:ReplayProtection` | no | `Store` (`Memory`=0, `SqlServer`=1). Outside Development, `Memory` needs `AcknowledgeSingleInstance` whenever the replay guard is in use (signing in Enforce, the service-assertion server, tickets); the same flag acknowledges the memory session store. |
| `Codelab:Security:SqlStore` | when a store is `SqlServer` | `ConnectionString`, `CommandTimeoutSeconds`, `EnsureSchemaOnStart`. |
| `Codelab:Security:Sessions` | no | claim types (`sub`, `sid`, `skid`, `sver`), `Store`, `ValidateOnEveryRequest`, `RequireSessionId`. `Store` = `Memory` outside Development needs `ReplayProtection:AcknowledgeSingleInstance`. |
| `Codelab:Security:Headers`, `:Cors`, `:RateLimiting` | no | HSTS, origins, `PermitLimit`, `WindowSeconds`, `TrustedProxies`, `ApplyGlobally`. |
| `Codelab:Security:Tickets`, `:Uploads` | when enabled | `Enabled` / `ReceiptsEnabled` plus their key rings; upload caps and extension lists. |
| `Codelab:Security:KeyGuards:ValidateNotPublishedMaterial` | no | `true` by default; `false` is refused outside Development. |
| `Codelab:Security:ServiceAssertions:Server` / `:Client` | per side | `AuthenticationBuilder.AddCodelabServiceAssertion(configuration)` / `IHttpClientBuilder.AddCodelabServiceAssertion(configuration)`. |

Everyday calls:

- **Identifiers:** `PublicId<Records>` in DTOs, route and query parameters (`{id:publicid}` on MVC routes); `PublicId<Records>.From(id)` server side.
- **Signing markers:** `.WithSignatureExemption(SignatureExemption.WholeRequest, "why")` on anonymous endpoints, `BodyOnly` on multipart uploads, `.WithUnsignedResponse("why")` on file downloads (attributes for MVC).
- **Revocation:** logout calls `ISessionRevocationStore.RevokeAsync(new SessionRevocation(sid, sessionExpiry))`; password change, deactivation and permission changes call `ISessionVersionStore.BumpAsync(userId)`.
- **Tickets:** `ISealedTicketService.Seal(new TicketRequest(purpose, subject, lifetime))` and `OpenAsync(purpose, token)`; a ticket opens once.
- **Uploads:** `FileSignatureSniffer`, `FileNames.SafeLeafName` / `TryResolveWithin`, `UploadCapCounter`, `UploadDigest`, `IUploadReceiptSigner`.
- **Purge hook:** the P5 jobs module runs `SecurityStorePurgeJob.RunAsync` (key `codelab-security-store-purge`) on its own schedule; the package schedules nothing.
- **SQL schema:** `SecuritySqlSchema.EnsureCreatedAsync` runs on start when a store is `SqlServer`; the DBA copy ships in the package as `sql/codelab-security-stores.sql` (idempotent).

## Extend
- **A new signed construction** (a token or a MAC): add a profile constant and build its bytes with `CanonicalFraming`, never by concatenation. Bind the protocol prefix (take a `SecurityProtocol`), derive keys with HKDF over a framed info, and register its options with a validator that calls `KeyRingGuard.Check`.
- **A new replay-protected family:** call `IReplayGuard.TryConsumeAsync(new ReplayNonce(scope, nonce, expiresAt))` with a scope prefix of its own (`ticket/`, `s2s/`) and treat `StoreUnavailable` as a refusal.
- **A new store with expiring rows:** implement `IExpiredEntryPurger` and register it; the purge job picks it up. Add its table to `Storage/Sql/codelab-security-stores.sql` behind an `IF OBJECT_ID(...) IS NULL` guard (never alter or drop).
- **A new upload type:** add its magic bytes to `FileSignatureSniffer.KnownSignatures`, then allow it in `Codelab:Security:Uploads:AllowedExtensions`.
- **Golden vectors (wave 3):** generate them with the public API (`SecurityProtocol.Create`, `CanonicalFraming`, `SignatureCanonicalForm`, `HmacSignature`, `SessionKeyDerivation`, `PublicIdKeyring` + `PublicIdCodec`). Fixture keys go on the denylist through `PublishedMaterial/published-material.fixtures.json` in the file format described under Rules.
- Every public type change updates `PublicAPI.Unshipped.txt` (RS0016/RS0017 fail the build otherwise).

## Rules
- Generated files in this folder (`CLAUDE.md`, `.editorconfig`, `BannedSymbols.generated.txt`, `CodeMetricsConfig.txt`) and `module.rules.yaml` are platform-owned. This package depends on no other Codelab package.
- No product literal anywhere: every wire name comes from `SecurityProtocol`. No key material in the repository: tests generate keys at run time.
- Every key ring passes `KeyRingGuard` at start: structure first, then the published-material denylist. The denylist is every embedded `PublishedMaterial/*.json`. Each file is `{ "keyDigestHashes": [...] }`, where an entry is `sha256(hexDecode(d))` for every digest `d` that `tools/extract/lib/key-material.mjs` `digestsOf` returns for a key value (`PublishedMaterialDenylist.EntryFor`). Hashing the digests once more keeps values that were themselves harvest fixtures out of the file. `published-material.source.json` is generated from `tools/extract/secret-digests.json` (kinds `config-secret`, `script-secret`, `test-fixture`, `vector-key`), and a test fails when it goes stale.
- Asymmetric keys are matched by key, not by text: `KeyMaterialDigests.Of` adds the SHA-256 of the DER `SubjectPublicKeyInfo` of any PEM (or DER) key, so a one-line, re-wrapped, SEC1 or public-half spelling of a published key is refused too. The service-assertion client checks its private key and the server checks every `TrustedServices[].PublicKeyPem`: trusting a published public key lets anyone holding its committed private half mint assertions.
- Enforcing controls move Off, then Report, then Enforce. Every 401 a control writes carries a `code` (`SecurityProblemCodes`); store failures answer 503 and never let a request through.
- MACs and digests are compared in constant time; parsers of attacker-controlled input return false and never throw.
- Time comes from `TimeProvider`; tests use `FakeTimeProvider`.

## Gotchas
- **Order matters:** `UseCodelabSecurity()` runs after authentication (it throws on the first request when signing is on and no authentication ran). The security headers do not depend on it: a startup filter puts them first, so CORS preflights and 404s carry them too. Call `app.UseCors()` before authentication.
- **The checks see the principal authorization will use.** `UseAuthentication()` authenticates only the default
  scheme. When an endpoint's policy names its own schemes (`[Authorize(AuthenticationSchemes = ...)]`,
  `AddAuthenticationSchemes`), for example bearer API endpoints beside a cookie default for SSO, or several schemes and
  no default, `UseCodelabSecurity()` authenticates those schemes first (the same `IPolicyEvaluator` call
  AuthorizationMiddleware makes), so request signing and `sid`/`sver` revocation still apply. It needs `UseRouting()`
  before it and `AddAuthorization()`.
- **Only the service-assertion scheme makes a service.** Signing and session checks skip a principal only when every
  authenticated identity was issued by `CodelabServiceAssertion`. A `codelab_service` claim in a user token (copied by
  an identity provider's claim mapping, say) proves nothing; a merged user and service principal is a user.
- **The PublicId codec is process-wide.** `UseCodelabSecurity()` installs it and round-trips a self-test id; host shutdown restores the previous one. Tests that start hosts or install codecs run in one serial xunit collection.
- **Minimal APIs:** a handler shaped like `RequestDelegate` (`HttpContext` in, `Task` out) discards its result (ASP0016); take `HttpRequest` or typed parameters. A body endpoint answers 415 at routing for a wrong content type, before authentication.
- **Response signing buffers** the body of verified requests; mark file endpoints `[UnsignedResponse]`. The capture swaps `IHttpResponseBodyFeature`, so writers that use the `PipeWriter` are covered too.
- **Memory stores are per process.** Outside Development the memory replay store (signing in Enforce, service assertions, tickets) and the memory session store are refused unless `Codelab:Security:ReplayProtection:AcknowledgeSingleInstance` is set; multi-replica deployments use `SqlServer`.
- **The browser proof covers `Request.Path` without `PathBase`.** Under an IIS child application (`PathBase` `/starter-api`) the SPA's API root is `/starter-api`, and @codelab/ng-security signs `/api/items`. Service assertions sign the full path (`PathBase` + `Path`), because a service client knows only the URL.
- **Body binding never trusts framing headers alone.** An HTTP/2 or HTTP/3 body may have no `Content-Length` and no `Transfer-Encoding`; the server's body-detection feature decides, so such a body is hashed (or refused over the cap), never treated as empty.
- **SQL store tests need SQL Server.** `Codelab.Security.Tests` creates a uniquely named database (`CodelabSecurityTest_<guid>`) on the server named by `CODELAB_TEST_SQL` (a server name such as `(localdb)\P2Proof`, or a connection string; default `(localdb)\MSSQLLocalDB`, the same as Starter.Integration.Tests) and drops it afterwards. With no reachable server those tests FAIL with a message naming the variable; they are never skipped.
- **Microsoft.AspNetCore.OpenApi** is referenced with `PrivateAssets="analyzers"`: its XML-comment generator needs the host's interceptor setting, so a host that calls `AddOpenApi` references the package itself.
- **Token shapes stay fixed across forks** (`m1_` PublicIds, `t1.` tickets, `r1.` receipts); only the prefix-bound AAD changes, so a token from another fork never authenticates.
