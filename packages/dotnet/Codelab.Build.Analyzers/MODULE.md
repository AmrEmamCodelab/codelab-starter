# Codelab.Build.Analyzers

## Purpose

The Roslyn analyzers behind the clean-code size and magic-number rules (ADR-012). Every diagnostic is an error by
default, so with `-warnaserror` (and without it) a violation fails the build.

| Id | Rule | Threshold key (default) | Base rule |
|---|---|---|---|
| CLB1001 | A member body has more code lines than the limit: methods, constructors, finalizers, operators, conversion operators, local functions, accessors, expression-bodied properties and indexers. | `codelab_method_lines` (40) | `base.clean-code` |
| CLB1002 | A source file has more code lines than the limit (reported on line 1). | `codelab_file_lines` (400) | `base.clean-code` |
| CLB1003 | A method, constructor, local function, delegate, indexer or class/struct primary constructor declares more parameters than the limit. | `codelab_parameters` (5) | `base.clean-code` |
| CLB1004 | A numeric literal that is not an allowed number and not already named. | `codelab_allowed_numbers` (-1,0,1), `codelab_exclude_tests` (true), `codelab_magic_numbers_enforced` (true) | `base.no-magic-values` |
| CLB1005 | An enum member without an explicit value (matched on syntax, so doc comments and attributes never hide it). | none | `base.enums-as-int` |

A code line is a line that holds at least one token: blank lines, comment-only lines, XML doc comments,
preprocessor directives and disabled code never count; a verbatim or raw string counts every line it spans.
Generated code (`<auto-generated>` headers, `*.g.cs`, `*.designer.cs`) is never analyzed.

## Use

Nothing to add per project. Codelab.Build.Sdk wires the analyzer into every project:

- Starter monorepo (source mode): `Sdk.targets` references this project as an Analyzer
  (`OutputItemType="Analyzer"`, `ReferenceOutputAssembly="false"`), so a change here needs no publish.
- Forks and other consumers (feed mode): the dll ships inside the Codelab.Build.Sdk package at
  `analyzers/dotnet/cs`; `tools/build.ps1 -Pack` puts it there. This project is never packed on its own.

Thresholds come from the rules files, never from code:

1. the module's generated `.editorconfig` (`thresholds` and `exemptions` in its `module.rules.yaml`), then
2. `rules/codelab.globalconfig` (the base values from `rules/base.rules.yaml`, for every project, including
   projects without a `module.rules.yaml` such as `tools/` and `tests/`), then
3. the built-in defaults in `Options/DefaultThresholds.cs` (equal to the base rules; a test fails when they drift).

A value that does not parse falls back to the next source; a broken key never switches a gate off.

What CLB1004 treats as already named (allowed anywhere in these initializers, e.g. `TimeSpan.FromSeconds(30)`):
`const` fields and locals, `readonly` and `static readonly` field initializers, property initializers, enum member
values, attribute arguments and parameter default values. Test projects are skipped while `codelab_exclude_tests` is
true; a test project is one whose MSBuild project name (`build_property.MSBuildProjectName`, made visible by
Codelab.Build.Sdk) ends in `.Tests`/`.Test`, or, without that property, whose assembly name does. `IsTestProject` is
not trusted: referencing Microsoft.NET.Test.Sdk sets it.

CLB1003 skips signatures the author does not own (`override`, explicit interface implementations, `extern`) and
record primary constructors (data shapes, not calls).

## Extend

- New diagnostic: add the id to `DiagnosticIds.cs`, a descriptor to `Descriptors.cs`, the analyzer under
  `Analyzers/`, a row in `AnalyzerReleases.Unshipped.md`, unit tests in `Codelab.Build.Analyzers.Tests`, and for a
  build gate a case in `SdkFixture/SdkBuildTests.cs`. Add the id to `rules/base.rules.yaml` `analyzers` and to the
  `base.no-analyzer-opt-out` pattern (it already matches `CLB\d{4}`).
- New threshold key: `Options/OptionKeys.cs`, `Options/ThresholdReader.cs`, `Options/DefaultThresholds.cs`, the
  rules engine's `lib/emitters/analyzer-settings.mjs` and `rules/rules.schema.json`, in one change. The rules-engine
  emitter test and `ThresholdReaderTests` fail when the C# keys or defaults drift from the rules.
- Release tracking: when the SDK ships, move the Unshipped rows to `AnalyzerReleases.Shipped.md` under the release.

## Rules

- Platform-owner review for every change (CODEOWNERS covers `packages/`).
- netstandard2.0 and `Microsoft.CodeAnalysis.CSharp` 5.0.0 (the .NET 10 GA compiler): never raise it above the
  compiler of the SDK pinned in `global.json`, or the analyzer fails to load (CS8032).
- Analyzers are stateless and concurrent (`EnableConcurrentExecution`); per-compilation state lives in the
  `ThresholdCache` created in the compilation-start action.
- No suppression mechanism of our own: a justified exception is a `module.rules.yaml` exemption
  (`base.no-magic-values`) or a threshold override, both reviewed by the platform owner.

## Gotchas

- This project cannot analyze itself (it would reference itself); its own code follows the same limits by review.
- Roslyn lower-cases `.editorconfig` keys; keep every key lower-case.
- The fixture builds in `SdkBuildTests` run the real SDK from a temp folder; they need the .NET 10 SDK resolved the
  way `tools/build.ps1` does (`CODELAB_DOTNET`, the private install, then the test host's dotnet).
